Primary author: Claude Sonnet AI (never human; authoring of this action item is reserved for Claude)

## What this is

The v1.9 golden gate is retired **NO-GO**: two local no-egress golden executions measured zero
finding recall against 34 frozen `present` opportunities in the golden manifest
(`results/v1.9-golden-opportunity-manifest.json`, `label_counts.present == 34`), which are the
identical 34 opportunities recorded as `missed_defect_opportunity_ids` in
`results/v1.9-golden-correction-ledger-v2.json`. Those 34 items are already-frozen, already-trusted
ground truth; nothing here relabels them.

ADR-0011 action item 3 asks, for engineering understanding only, whether each of those 34 misses
would in principle be **file-local** (fully resolvable within one local scope) or **cross-module**
(requires resolving evidence across file/module boundaries) under the LLM-PRV-001, LLM-EVL-001, and
LLM-EVL-002 evidence contracts. This is a retrospective, descriptive exercise: it asks how catchable
each miss plausibly is with local single-file resolution versus how much of the miss reflects an
inherent cross-module resolution gap. It produces no new opportunity, no new label, and no detector
run.

## What this is not

- **Not rescoring.** No `ground_truth_label`, `evidence_scope`, or manifest hash in any frozen v1.9
  artifact was touched. Every label is used exactly as frozen.
- **Not a release gate.** This document is not bound into `release-thresholds.json`,
  `pre-result-commitment.json`, or any automatic-NO-GO evidence chain, and `compute-metrics.mjs`
  does not consume it.
- **Does not reverse the NO-GO.** `results/v1.9-golden-gate-no-go.json` remains the canonical v1.9
  decision. This note and its JSON record do not change that decision, do not reopen the retired
  golden or withdrawn untouched cohort, and do not authorize running the detector again.
- **Does not authorize a performance claim.** The classification below (34/34 cross-module, 0/34
  file-local) is not a recall, precision, or "catchable fraction" percentage and must not be quoted
  as one. See Limitations.

## Scope actually covered

Action item 3 defines an explicit file-local/cross-module contract for three rules:

- `LLM-PRV-001` — same local result-producing scope for model invocation and result.
- `LLM-EVL-001` — complete local case iteration, aggregate calculation, and direct result emission.
- `LLM-EVL-002` — one local producer and one explicit local judge resolving to the same literal
  model identity.

Those three rules cover 24 of the 34 present opportunities. The remaining 10 span `LLM-AGY-001` (2),
`LLM-VAL-001` (2), `LLM-IOH-001` (2), and `LLM-DAT-001` (4) — rules the action item did not
enumerate a contract for. For those 10 rows, the JSON record applies the equivalent local/resolved-
inter-procedural distinction already frozen in `docs/packs/free-llm-v1-rule-contract.md`'s own
per-rule confidence language (`high` for a direct local path, `medium` for a resolved supported
inter-procedural path), and flags each such row for owner confirmation that this extension is in
scope for action item 3.

## Result

All 34 rows classify **cross-module**: 0/34 file-local, 34/34 cross-module. Every row is flagged for
owner review.

This is not because the 34 underlying repository defects are known to be architecturally cross-file
in every case — it is because every one of the 34 frozen `evidence_scope` entries pins a single
file+line anchor, every contract above requires confirming a *second* local component (a producer/
judge pair, an iteration+aggregation+emission chain, or an invocation+result pair) that a single-
point anchor does not itself locate, and whole-file source bytes for the golden cohort are not
committed to this repository (`protocol.md` §5 step 8 and the calibration README: only
`source_evidence_index_sha256` is public; the bytes and blob/tree proofs live in restricted internal
evidence outside every Git working tree). One golden repository's own execution receipt
(`Ankitha-GS/rag-qa`) additionally records that its GitHub origin no longer resolves, which rules out
live re-fetch as a reliable substitute. Given no committed artifact differentiates the missing second
component per opportunity, every row is genuinely ambiguous under this document's own definition —
and per the governing instruction for this action item, genuine ambiguity is classified
cross-module and flagged for owner review rather than guessed as file-local.

## Limitations

- Zero of the 34 rows could be confirmed file-local from committed evidence; this reflects an
  evidence gap in what is committed to the repository, not a confirmed architectural finding about
  the 34 underlying repositories.
- 10 of the 34 rows (all `LLM-AGY-001`, `LLM-VAL-001`, `LLM-IOH-001`, `LLM-DAT-001` rows) use a
  contract derived by analogy rather than one of the three contracts action item 3 named explicitly,
  and need owner sign-off that this extension is the intended scope.
- No repository source, whole-file byte, or Git blob/tree proof was read, fetched, or reconstructed
  to produce this document; only already-committed v1.9 JSON artifacts (`evidence_scope` path/line/
  hash, the correction ledger, and the rule-contract documents) were inspected. No untouched-cohort
  artifact was accessed, listed, run, or spent.
- Publication does not depend on the outcome: this record is published whether the split is 0/34,
  34/34, or anything in between, and is retained as calibration evidence either way.
