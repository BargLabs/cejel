## Result (affirmative)

**0/34 file-local; 34/34 cross-module — every row resolved with a concretely cited second file or
module, not the ambiguous fallback.**

This differs from the baseline's own 0/34 in kind, not just in number: the baseline's 0/34 was a
mandated fallback recorded *because* the required evidence could not be resolved from committed
metadata alone. This document's 0/34 is an **affirmative architectural finding** — for every one of
the 34 rows, read-only inspection of the actual checked-out source identified a specific second
file (and in three cases a second language/runtime: `AgentRuntime.kt` for Shelly's two `LLM-AGY-001`
rows, and `plugins/sreyun_actions.py` for one of aiops-monitor's `LLM-VAL-001` rows) that the rule's
required-evidence chain genuinely needs beyond the anchored file. No row's second-file dependency
remained unresolved, so `unresolved_rows` in the JSON record is empty.

Representative patterns observed across the 8 repositories:

- **Producer/judge split across files** (`LLM-EVL-002`, 15/34 rows): in every repository with this
  rule, the judge model call and the producer/target model call are configured in different files
  (e.g. `aegis-eval-harness`: judge in `evaluators.py`/`config.py`, producer in `target.py`,
  combined only in `runner.py`; `rag-qa`: judge hardcoded in `evaluator.py`, producer's
  `RAGConfig.model` in `rag_engine.py`).
- **Presentation/aggregation sinks separated from the model call** (`LLM-PRV-001`, `LLM-EVL-001`,
  3 + 6 rows): anchors landing in report/dashboard/CLI-display code (`nexa-gauge`'s `report.py`/
  `graph.py`, `insurance-llm-framework`'s `app.py`, `memoturn`'s `dashboard.tsx`) consistently read
  already-computed values; the actual model invocation and/or case-iteration logic sits in a
  distinct node/benchmark/server module.
- **Cross-language/cross-runtime authority and secret-flow boundaries** (`LLM-AGY-001`, `LLM-DAT-001`,
  2 + 4 rows): Shelly's app-act Tier-B trust gate is explicitly, by the code's own comment, handled
  *exclusively* by native Kotlin (`AgentRuntime.kt`); its terminal-context secret source is resolved
  in a separate `lib/ai-pane-context.ts`; aiops-monitor's terminal-session-to-AI-prompt path crosses
  from `terminal.go` into `sre_api.go`'s `buildTerminalSummary`.
- **Generic transport/dispatch layers blind to model provenance** (`LLM-VAL-001`, `LLM-IOH-001`,
  2 + 2 rows): Velune-CLI's WebSocket transport and markdown renderer, and aiops-monitor's tool
  dispatch loop, are all generic mechanisms whose callers (a different file in every case) are
  where the rule-relevant validation or model-output provenance would have to be confirmed.
