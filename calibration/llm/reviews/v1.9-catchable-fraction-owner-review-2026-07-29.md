## What this is

The baseline classified all 34 already-frozen, already-trusted `present` opportunities from
`results/v1.9-golden-correction-ledger-v2.json` using **only committed JSON metadata**. This
owner-review document redoes the same 34-row file-local/cross-module architecture question with
**read-only source inspection** of the 8 implicated golden repositories, already checked out
read-only at their frozen commit SHAs under `/private/tmp/cejel-v19-owner-review-golden-20260729`.

Three rounds of isolated Codex AI review have progressively tightened both the evidentiary standard
and the internal consistency of how that standard is applied. The governing evidence boundary (round
2, held in round 3): each row may cite, as affirmative proof, only its own evidence_scope anchor
file's content (including comments) and that same file's own direct local imports. Reverse callers,
repository-wide search/`find` discoveries, same-package siblings with no import statement, and
package-internal files that are not themselves an import target are **not** admissible. Round 3 adds
an explicit **full-chain treatment** rule for multi-element required-evidence checklists (such as
`LLM-EVL-002`'s producer + judge + identity-equality): proving that only ONE required element is
external is not sufficient for a confident classification — all required elements must be admissibly
resolvable, or the row is recorded ambiguous.

  they do not themselves constitute a full trace of that second file's contents in every case (e.g.
  `AgentRuntime.kt` and `velune/models/probes.py` were not opened — their existence and role are
  established by the anchor file's own comment or import statement, per `source_access_accounting`).

  truth is correct — only where, architecturally, the decisive evidence for the applicable rule
  physically lives relative to the anchored file, and only using evidence admissible under the
  strict per-row boundary and full-chain treatment described above.
- The 10 rows outside the three explicit action-item-3 contracts remain pending explicit owner scope
  acceptance regardless of how confidently their architecture question was answered here.
- 16 of 34 rows are recorded ambiguous. Most because the strict boundary excludes the only
  second-component evidence found (a reverse caller, a same-package sibling, or a package-internal
  file), or because only part of a multi-element required-evidence chain could be admissibly
  resolved (full-chain treatment) — not because no plausible second file exists, only because the
  full chain cannot be named via an admissible path from the row's own anchor file. For one row
  (`976a81ef...`), it is specifically because two independent reviewer passes disagreed about the
  classification itself. This is an honest reporting of an evidence-boundary gap, an incomplete
  evidence chain, or genuine reviewer disagreement — not a claim that these rows are actually
  file-local.
