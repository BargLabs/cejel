## Limitations

- Second-component citations identify the specific file/module the required evidence chain needs;
  they do not themselves constitute a full trace of that second file's contents in every case (e.g.
  the exact runtime behavior of `AgentRuntime.kt` or `velune/models/probes.py` was not further
  decompiled/executed — their existence, naming, and role were confirmed by reading the calling
  file's own imports/comments, consistent with the read-only, no-execution constraint on this
  review). `source_access_accounting` in the JSON record distinguishes files whose content was
  actually opened from files only confirmed to exist by name.
- This document does not attempt to resolve whether the original opportunity's `present` ground
  truth is correct — only where, architecturally, the decisive evidence for the applicable rule
  physically lives relative to the anchored file.
- The 10 rows outside the three explicit action-item-3 contracts remain pending explicit owner scope
  acceptance regardless of how confidently their architecture question was answered here.
- 7 of 34 rows are recorded ambiguous, not because no second file could plausibly exist, but because
  the permitted evidence_scope-plus-direct-imports inspection boundary could not concretely name one
  (or, for the `Velune-CLI` markdown-renderer row, because the file that was opened did not confirm
  a sink). This is an honest reporting of an evidence gap, not a claim that these rows are actually
  file-local.
- This reconciliation itself surfaced one defect (the two `nexa-gauge` `LLM-PRV-001` citations) that
  neither Codex pass raised, disclosed for transparency in `review_and_reconciliation`. This is not
  evidence that all remaining citations are now defect-free — only that this specific class of error
  (citing a file the anchor file does not actually import) was checked for and corrected where found
  during this pass.
