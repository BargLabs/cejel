## Harness

This experiment uses harness v2 (`../public-delta-harness/`) unchanged, as merged in #495 at
`d3dbea3cd5335114702804f68fe489824be18236`. The plan schema is `cejel-public-delta-v2`. `RUN.md`
there is the procedure.

One addition is fixed here, before any run: `byte-identity.mjs`, with its test,
`byte-identity.node-test.mjs`. Harness v2 does not compare serialized report bytes, and E5 needs
that comparison, so the method is fixed now and not chosen after outcomes exist. Per pair and per
public row, the script compares the actual report files written by `score-arm.mts`:

- byte-for-byte;
- after removing only the top-level `rubricBehaviourFingerprint` line;
- after removing only the lines of the pair's `presentationOnly` fields.

It refuses a field that is not a one-line top-level string. It also records whether every run's
manifest has the same target identity vector (name, commit, commit count).

The script writes public row names and booleans only. It reads no harness file except through
`common.mjs`'s exported loaders.

### What `presentationOnly` can and cannot carry

`presentationOnly` takes top-level report fields only, and may not name `criteria`. Two changes
from this release live inside `criteria`, in evidence labels and metric conditions:

- the #490 CI citation label;
- the workspace-scripts disclosure (#479).

The comparison's criterion projection does not read them. That projection is status, score,
metric name, value, max and weight, and finding counts by severity. So these two changes cannot
register as a scoring move. They show only as `criteria` in `changedTopLevelFields` and as a lower
`identicalAfterPresentationRemoval` count. Plan field `publicRows`: 23.

## How each value is read

These are sources, not thresholds. Every scalar the harness emits is reported, whether or not
it bears on a forecast.

- **E0:**
  - From `paired-result.json`: each run's `completed` and `errors`, and its `sourceHead`, read from
    the manifest that `score-arm.mts` writes after checking source HEAD and clean tracked source.
  - From `byte-identity.json`: `targetIdentityIdenticalAcrossRuns`. `score-arm.mts` checks each
    target's identity before and after every scan.
  - **Existing outputs refused:** after each run writes its manifest, the same command is invoked
    once more. It must refuse with `run output already exists; never overwrite a run`. It refuses
    after verifying targets and before importing the scanner, so it scores nothing. It is invoked
    only when that run's `_manifest.json` exists.
- **E1:** `release-v17` `summary.unexpectedCriteria`, and the criterion ids and metric names in
  each row's `movedCriteria`.
- **E2:** the direction of each moved criterion score in `movedCriteria`.
- **E3:**
  - `release-v17` `summary.scoringRowsMoved`;
  - per moved row, the direction of its overall, code and process scores and of each moved
    criterion;
  - whether its B3 moved, and whether the target declares workspaces in the forms #479 reads.
- **E4:** the `item6-v26` A5 and A2 rows in `movedCriteria`. Which finding appeared or disappeared,
  and whether a row names a claim-reconciliation artifact, are read from the local raw reports and
  reported as per-row facts, without evidence text.
- **E5:** `release-v17` `summary.fingerprintsChanged`, and `byte-identity.json`
  `pairs.release-v17.identicalAfterFingerprintRemoval`.

## Integrity

- Each run runs once.
- A failed row is recorded and never retried.
- No target pin, threshold, weight or forecast changes.
- A run is never split between hosts.

A protocol failure before any score may be corrected without changing this file. After scoring
starts, a correction is an erratum and a successor protocol, never reuse of outputs under a changed
procedure.
