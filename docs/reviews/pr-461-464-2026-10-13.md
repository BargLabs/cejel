## P2: distinguish command execution from package resolution (#462)

Location: `src/npx-version-guard.ts:56–64` at the reviewed head.

`npm_lifecycle_event=npx`, the checkout's package metadata, and a local bin directory first in PATH do not establish that npm resolved a Cejel package request. `npm exec --call` also supplies all of them when executing an explicit command without any package request. If that command deliberately runs another Cejel version, the guard falsely says npm resolved the checkout version and ran the PATH binary instead.

Reproduced end to end, offline: built the exact PR head (version 0.6.3), created a temporary working directory with package.json containing name `@cejel/cejel` and version `0.6.4`, then ran:

```sh
npm exec --offline --call 'node /private/tmp/cejel-review-462/dist/index.js --version'
```

stdout was `0.6.3`; exit status was 0. stderr falsely said npm resolved the 0.6.4 checkout and ran Cejel on PATH instead. The command explicitly named the 0.6.3 artifact, and requested no package/version resolution. The same false diagnostic applies to an intentional `npx --call 'cejel …'` command using a different installed version. Recognize the call/command mode and remain silent when package resolution is unknown; add this negative control.
